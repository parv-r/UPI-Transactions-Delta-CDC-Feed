## UPI Transactions Delta CDC Feed

This repository showcases a Change Data Capture (CDC) workflow to process UPI (Unified Payments Interface) transaction data in Databricks using Delta Lake. The workflow demonstrates generating mock data, capturing changes, processing the CDC feed, and performing transformations to calculate key business metrics like total sales, refunds, and net sales.

#### Workflow Overview
  1. Mock Data Generation: Generate synthetic merchant transaction data and write it into a Delta table (upi_transactions).
  2. Change Data Capture (CDC): Simulate updates or new records to the upi_transactions table to mimic real-world change data capture scenarios.
  3. CDC Feed Processing: Continuously monitor and process the CDC feed to identify changes in the transaction data.
  4. Transformations and Aggregations: Apply transformations to calculate merchant-wise:
  - Total Sales
  - Total Refunds
  - Net Sales

#### Steps to Set Up

  1. ##### Mock Data Generation Notebook
  - ##### Purpose: 
    - Mimics real-world merchant transactions.
  - ##### Steps:
    - Generates synthetic transaction data.
    - Writes the data into a Delta table named upi_transactions.
    - Simulates CDC events by updating existing records or adding new records to the table.

  2. ##### CDC Feed Processing Notebook
  - ##### Purpose: 
    - Reads and processes the CDC feed from the upi_transactions table.
  - ##### Steps:
    - Reads changes from the Delta table.
    - Applies necessary transformations to calculate key metrics.
    - Outputs aggregated metrics like total sales, refunds, and net sales.

  3. ##### Databricks Workflow for Continuous Processing
  - ##### Task:
    - Create a Databricks task to run the CDC feed processing notebook continuously.
    - Ensures that any changes in the upi_transactions table are captured and processed in near real-time.

  4. ##### Manual Mock Data Trigger
  - The mock data generation script is designed to be run manually as needed to simulate real-life CDC scenarios.

#### Key Features
  - Change Data Capture (CDC) Simulation: Demonstrates how to mimic real-life CDC scenarios by updating or inserting records into the Delta table.
  - Continuous Processing: Ensures the CDC feed is continuously monitored and processed in real-time.
  - Business Insights: Calculates merchant-level metrics like total sales, refunds, and net sales using PySpark transformations.
  - Delta Lake Integration: Leverages Delta Lake for efficient data storage and change tracking.

#### Technologies Used
  - Databricks: For creating notebooks and workflows.
  - Delta Lake: To handle data storage and CDC.
  - PySpark: For data generation, processing, and transformations.

#### How to Run
  1. Mock Data Generation:
  - Open and run the upi_merchant_pay_trnsc_mock_data.py notebook to generate synthetic transaction data.
  - Rerun the notebook as needed to simulate CDC events.
  2. CDC Feed Processing:
  - Deploy the cdc_merchant_aggregation.py notebook as a task in Databricks.
  - Configure the task to run continuously for real-time CDC feed processing.
  3. View Results:
  - Check the aggregated metrics like total sales, refunds, and net sales generated by the processing notebook.
